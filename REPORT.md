# Постобработка OCR паспорта РФ — отчёт

## Прогноз для test

| | Документов |
|---|---|
| Всего в test | 2000 |
| **Принимаю** | **1236** (61.8%) |
| **Из них с ошибкой (прогноз)** | **≈ 8–9**, вероятный диапазон 3–16 |
| из них ошибок, которые можно было поймать | ≈ 1 (0–4) |
| из них опечаток разметки, которые поймать нельзя | ≈ 7 |

Откуда цифры. На 5-кратной кросс-валидации по train (3000 документов) принято 1897, с ошибкой 13 (0.69%). Из этих 13 одиннадцать — опечатки в разметке (см. ниже), и ещё в двух потеряна точка в «Месте рождения». Если умножить 0.69% на 1236 принятых, получится 8.5. Диапазон учитывает неопределённость доли ошибок (95% интервал Пуассона для 13 событий — от 7 до 22 на 1897) и случайный разброс на самом test. Паспорта, недействительные на 01.10.2026, скрипт отклоняет сам: в test таких 49. Если разметка test чище, чем train, ошибок будет 1–3.

Распределение test похоже на train. Медианы `sharpness`, `doc_px`, `glare` и доля документов без MRZ (5%) почти совпадают. Отличается только смесь источников: `mobile_v2` в test 22%, в train 10%. Доли принятых по источникам на test совпадают с CV: web 62.5% против 62.9%, mobile 65.2% против 65.1%, mobile_v2 55.0% против 58.2%. Это косвенно подтверждает, что ведёт себя скрипт так же. Отсутствие ошибок на test этим не проверить.

## Как устроено решение

Главный принцип: документ принимается, только если **каждое** из 10 полей подтверждено источником, независимым от прочитанного текста визуальной зоны. Всё, что выучено из данных, строится из train при каждом запуске (`build_model`): словари, таблицы путаниц и частоты. Поэтому кросс-валидация честная, и разметка документа никогда не попадает в его же модель.

1. **Серия и номер, даты, код, пол.** Эти поля продублированы в строке 2 MRZ под контрольными цифрами ICAO 9303 (веса 7-3-1). Если viz совпала с MRZ, поле принято. Если не совпала, а контрольная цифра MRZ сходится, берётся значение из MRZ. Если MRZ нет или она нечитаема, поле принимается по viz только с уверенностью ≥ 0.99 (для `mobile_v2` так не делается).
2. **ФИО.** Скрипт строит строку 1 MRZ, какой она должна быть по viz (транслитерация паспорта РФ: Й→Q, Ч→3, Ш→4, Я→8, …), и выравнивает её с прочитанной. Для каждого расхождения он сравнивает две гипотезы: «ошиблась MRZ» и «ошиблась viz». Правдоподобие гипотезы = как часто такая путаница была у этого источника в train × (неуверенный символ ошибся, уверенный прав). Нужен перевес в 5 раз. Вставлять в viz символы по MRZ нельзя, удалять их из viz можно только при уверенности viz < 0.98. Е и Ё в MRZ не различаются, поэтому Ё → Е.
3. **«Кем выдан».** Сначала ищется точное или почти точное (≤ 3 правки в неуверенных символах) совпадение с названием, которое встречалось в train при том же коде подразделения. Если не нашлось, поле проверяется как обычный текст (п. 4).
4. **«Место рождения» и остальной текст.** Каждое слово должно пройти одно из условий:
   - все символы с уверенностью ≥ 0.93;
   - слово встречалось в train ≥ 3 раз, и уверенность ≥ 0.9;
   - его можно исправить на частое слово из словаря заменой одного неуверенного символа (< 0.9), и такая путаница встречалась у viz.

   Отдельно ловятся потерянные символы: уверенно прочитанное слово отклоняется, если частое слово из словаря длиннее его на один символ («С» → «С.», «ОССИИ» → «РОССИИ»). Ещё отклоняются поля, где строки текста не покрывают рамку поля, то есть потеряна целая строка.
5. **Логика.** Паспорт выдан не раньше 14 лет. Действителен на 01.10.2026: меняется в 20 и 45 лет, льготные 90 дней не считаются, такие документы отклоняются. Пол согласован с окончанием отчества.

## Что я выяснил о данных

- **В разметке есть опечатки.** «ЕВТЕНИЙ», «ФАРИЛА», «ЬАЛТРУШЕЕВИЧ», «КИТУРКС». При этом viz и MRZ независимо и уверенно читают нормальное имя («ЕВГЕНИЙ», EVGENIQ). Такое бывает примерно у 0.4% документов, почти всегда в фамилии и имени. Только по выводу модели это не отличить от верного документа, поэтому это нижняя граница ошибок для любого решения. Её стоит учитывать при сравнении результатов.
- **Уверенность модели не откалибрована.** У `mobile_v2` 97% символов имеют conf = 1.0, у `web` — 5%. Поэтому пороги задаются отдельно для каждого источника, а для `mobile_v2` уверенность почти не используется.
- **Уверенность не ловит пропавшие символы и строки.** У потерянного символа нет своей уверенности, остальные прочитаны уверенно. Ошибки «С» вместо «С.» и потерянная вторая строка «Места рождения» составляли половину ошибок первой версии.
- **Какой источник ошибся, видно по типу путаницы, а не по уверенности.** Viz путает похожие кириллические буквы (Л/А, В/Р, Т/Г, С/О, Н/И), MRZ — похожие латинские и цифры (I/1, O/0, A/4, U/V, N/H) и вставляет лишнюю K в заполнитель. При этом ошибки с уверенностью 1.0 есть у обоих.
- **Справочник DaData мало помогает для текста «Кем выдан».** Формулировки в нём другие («ОТДЕЛЕНИЕМ УФМС…»), с разметкой точно совпадает около 6% названий. Кроме того, 43 кода из разметки в справочнике отсутствуют. Использовать отсутствие кода как признак ошибки нельзя: на train это отсекало 25 верных документов.
- **Разметка «Кем выдан» повторяется для одного кода.** Код подразделения из test встречается в train у половины документов, и для таких документов название берётся из словаря «код → название».

## Как проверял

`cv.py` прогоняет 5-кратную кросс-валидацию. `python cv.py grid` дополнительно прогоняет варианты, каждый меняет один параметр. Ход работы (принято / ошибок кроме опечаток разметки):

- просто склеить строки OCR: 1680 / 1320;
- первая версия с подтверждением по MRZ: 959 / 30 (на всём train);
- + потерянные строки, Ё, пороги по источнику: 1451 / 0;
- + ФИО по таблицам путаниц, исправления по словарю: 1812 / 2;
- + поля без MRZ по уверенности viz: **1897 / 2**.

Чувствительность выбранных порогов (CV):

| Изменение | Принято | Ошибки |
|---|---|---|
| порог текста 0.93 → 0.90 | +34 | +16 |
| порог слов из словаря 0.90 → 0.85 | +14 | +1 |
| поля без MRZ: порог 0.99 → 0.98 | +43 | +2 |
| `mobile_v2`: порог текста 0.999 → 0.995 | +9 | +5 |

Все выбранные пороги стоят на шаг сетки от точки, где ошибки начинают расти. Значит, на test, где распределение похоже на train, сюрпризов быть не должно. Но пороги подобраны по той же CV, поэтому прогноз немного оптимистичен.

## Что можно улучшить

- **Отказы по «Месту рождения» и «Кем выдан».** Это около половины отказов на test: неуверенное слово, которого нет в словаре (обычно название населённого пункта). Помог бы словарь топонимов (например, ОКТМО/ФИАС, офлайн) или языковая модель символов, обученная на разметке.
- **Пропавшая точка в коротких сокращениях** («ПГТ» / «ПГТ.»): это обе ошибки, оставшиеся на CV. Можно учитывать ширину рамки строки относительно числа символов.
- **Калибровка уверенности.** Вместо ручных порогов можно обучить калибровку уверенности для каждого источника (изотоническая регрессия на train) и задать порог на вероятность ошибки документа.
